# Product plan and verification status

## Product shape

Still is a quiet personal assistant, not a live conversational agent. The user records or types a thought, saves it locally, then may request a transcript or bounded extraction. The assistant can prepare editable proposals and gather relevant personal context. It cannot approve its own proposal. Every approval binds to the exact current revision; editing the transcript, recipient, destination, time, title, or body invalidates that approval. Remote provider sends and calendar writes require a separately connected, verified OAuth identity and a distinct user action. On-device calendar writes instead require explicit full calendar permission, a selected writable calendar, exact approval, and a separate user action; they do not require OAuth or AI access.

The full intended scope includes personal memory and rule editing, recorded-audio transcription, bounded Luna analysis, Gmail and Microsoft identity-specific draft/send flows, inbox and calendar sync, reminders, searchable Markdown, export/import, privacy controls, and an iOS beta release. The product is a single-turn assistant: it should answer questions from local context, summarize, and propose decisions/actions, without adding live conversation. Tasks need an open/completed lifecycle independent of whether an external action received an acceptance receipt. Voice-relative dates need a captured timezone and timestamp anchor. Manual reply drafts can use verified saved message metadata and explicitly loaded, bounded selected-message text. HTML is converted to plain text without rendering and always treated as an excerpt. A separate explicit action can generate reply text from that selected context; it returns body text only and does not create a proposal, draft, or send. Real provider retrieval and model behavior remain unverified. Replies bind `replyTo`, `inReplyTo`, and `references` to the saved source. Native iOS calendars (EventKit) are a separate on-device source with permission and ownership checks, independent of OAuth accounts. Future third-party providers should use an explicit connector registry; WhatsApp is out of scope. Import/restore must exclude credentials, verified identity state, and executable approvals.

## Setup gates

Before provider testing, the user needs an Azure Speech resource/key and an Azure OpenAI resource with a deployment and key selected for this application. The requested Codex model label “GPT-6 Luna” is not proof that a corresponding public Azure deployment exists; model availability, deployment naming, API compatibility, and price must be checked against the user's resource tomorrow. For account integrations, register Google and Microsoft public clients with provider-supported authorization-code-plus-PKCE redirects; do not bundle client secrets. The application needs its final bundle identifier, redirect URI registrations, Apple signing, and required provider review/consent. Browser preview keys are volatile; browser direct-provider requests have not been proven to satisfy CORS.

Before external execution, validate the active account, recipients (including all copied recipients), subject/body, attachments, calendar destination, attendees, and due time against the approved immutable payload. A provider acceptance receipt is not delivery confirmation. An ambiguous timeout enters a reconciliation state and must not trigger an automatic blind retry.

## Acceptance checks by phase

1. **Local workflow:** clean install, blank state, capture/manual note, offline save, transcript edit, delete, document edit, reload persistence, browser export, no fake accounts.
2. **Audio:** permission denial, pause/resume, cancel confirmation, interruption recovery, max length, offline stop then reopen/playback, IndexedDB quota retry, audio preservation after transcription error.
3. **Reasoning:** bounded context and output, exact evidence quotes, no extra prose, Luna effort none/low only, no auto-send, budget enforcement, repeated-attempt caps, and no silent fallback from provider error to mock.
4. **Approval:** mutate each bound field after approval and confirm invalidation; race two execute actions; restart while dispatching; handle provider accepted-but-unknown; reconcile rather than duplicate.
5. **Identity and sync:** two Google accounts and two Microsoft accounts, reconnect/revocation, per-account cursor, duplicate notification, expired cursor/full resync, non-writable calendar, and one user's identity never used for another account's draft.
6. **Native release:** physical iPhone development build; microphone denial/interruption/lock; Keychain write/delete/reinstall; system browser PKCE redirects; timezone/DST local notification; real AAC provider transcription; background/force-quit behavior; export and restore. Web export is not a substitute.
