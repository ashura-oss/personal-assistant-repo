# Product plan and verification status

## Product shape

Still is a quiet, note-centered personal assistant. The current flow lets the user record or type a thought, save it locally, then request a transcript or bounded extraction. OpenRouter Batch note assistance and queued text chat use explicit saved jobs; chat turns are retained in local immutable conversation history. Live voice conversation is out of scope. The assistant can prepare editable proposals and gather relevant personal context. It cannot approve its own proposal. Every approval binds to the exact current revision; editing the transcript, recipient, destination, time, title, or body invalidates that approval. Remote provider sends and calendar writes require a separately connected, verified OAuth identity and a distinct user action. On-device calendar writes instead require explicit full calendar permission, a selected writable calendar, exact approval, and a separate user action; they do not require OAuth or AI access.

The full intended scope includes personal memory and rule editing, recorded-audio transcription, bounded Luna analysis, Gmail and Microsoft identity-specific draft/send flows, inbox and calendar sync, reminders, searchable Markdown, export/import, privacy controls, and an iOS beta release. The intended assistant should answer questions from local context, summarize, and propose decisions/actions through explicit requests; queued text chat and explicit answer-only refinement are implemented at source, while live voice conversation is out of scope. Tasks need an open/completed lifecycle independent of whether an external action received an acceptance receipt. Voice-relative dates need a captured timezone and timestamp anchor. Manual reply drafts can use verified saved message metadata and explicitly loaded, bounded selected-message text. HTML is converted to plain text without rendering and always treated as an excerpt. A separate explicit action can generate reply text from that selected context; it returns body text only and does not create a proposal, draft, or send. Full provider retrieval and model behavior remain unverified; one synthetic OpenRouter Batch request has been verified. Replies bind `replyTo`, `inReplyTo`, and `references` to the saved source. Native iOS calendars (EventKit) are a separate on-device source with permission and ownership checks, independent of OAuth accounts. Future third-party providers should use an explicit connector registry; WhatsApp is out of scope. Import/restore must exclude credentials, verified identity state, and executable approvals.

## Setup gates

Before Azure testing, the user needs an Azure Speech resource/key and an Azure OpenAI resource with a deployment and key selected for this application. OpenRouter Batch note jobs are wired for explicit submission and status checks; validate the provider's behavior beyond the one synthetic request before relying on it. OpenRouter Speech has a separate explicit saved-recording upload path; validate it with the intended provider account and media on a real device before relying on it. For account integrations, register Google and Microsoft public clients with provider-supported authorization-code-plus-PKCE redirects; do not bundle client secrets. The application needs its final bundle identifier, redirect URI registrations, Apple signing, and required provider review/consent. Browser preview keys are volatile; browser direct-provider requests have not been proven to satisfy CORS.

Before external execution, validate the active account, recipients (including all copied recipients), subject/body, attachments, calendar destination, attendees, and due time against the approved immutable payload. A provider acceptance receipt is not delivery confirmation. An ambiguous timeout enters a reconciliation state and must not trigger an automatic blind retry.

## Acceptance checks by phase

1. **Local workflow:** clean install, blank state, capture/manual note, offline save, transcript edit, delete, document edit, reload persistence, browser export, no fake accounts.
2. **Audio:** permission denial, pause/resume, cancel confirmation, interruption recovery, max length, offline stop then reopen/playback, IndexedDB quota retry, audio preservation after transcription error.
3. **Reasoning:** bounded context and output, exact evidence quotes, no extra prose, Luna effort none/low only, no auto-send, budget enforcement, repeated-attempt caps, and no silent fallback from provider error to mock.
4. **Approval:** mutate each bound field after approval and confirm invalidation; race two execute actions; restart while dispatching; handle provider accepted-but-unknown; reconcile rather than duplicate.
5. **Identity and sync:** two Google accounts and two Microsoft accounts, reconnect/revocation, per-account cursor, duplicate notification, expired cursor/full resync, non-writable calendar, and one user's identity never used for another account's draft.
6. **Native release:** physical iPhone development build; microphone denial/interruption/lock; Keychain write/delete/reinstall; system browser PKCE redirects; timezone/DST local notification; real AAC provider transcription; background/force-quit behavior; export and restore. Web export is not a substitute.

### Recovery and privacy backlog

- **Phase 28 (historical prerequisite) — exact current snapshot reader.** The optional reader obtains raw persisted JSON/schema under the store queue, applies a 16 MiB UTF-8 byte limit, and performs a generation-checked transaction without mutating the baseline. It returns unparsed data for caller validation and is exposed only where supported.
- **Phase 29 implemented — selective proactive-rule quarantine recovery.** The controller prepares a five-minute plan bound to the full persisted snapshot, privacy epoch, and generation, followed by exact `RESET RULES` confirmation. A private version-1 sidecar in the existing state store retains exact JSON evidence, digest, byte count, and operation UUID in at most four immutable archives (256 KiB each, 1 MiB total); it never truncates or evicts. The atomic change archives the quarantined proactive value, resets only rules/candidates/dismissals/snoozes, and clears that active quarantine. It preserves all non-proactive/private sibling state, including mail-alert receipts; independently valid consents are revoked with durable cancellation intents. Existing notifications may remain until separate reconciliation verifies their removal. Corrupt mail data cannot create native notification authority. Malformed archive evidence remains private and blocks recovery. Reset itself makes no provider, model, or native notification call. Archives stay out of public state, model context, and portable backup/import; full-state privacy erasure includes them.
