## Implementation pass 10 · selected-message text and generated reply text (2026-10-13)

- Message text is loaded only after an explicit user action. The cache stores a source-bound snapshot of the selected message's bounded plain text or provider-supplied snippet; it does not claim to hold the whole thread. The composer shows the actual text, representation/completeness, omissions, byte count, and observation time. A snippet fallback requires explicit confirmation before it can be used for generation.
- Reply generation is a separate explicit action. The model receives the selected-message text plus the user's distinct optional brief and, only when selected, one saved note transcript. Brief and selected note together are capped at 4 KB; policy context is capped at 4 KB; selected body context is capped at 16 KB; the serialized request follows the configured byte limit; output is capped at 8 KB. Generated content is body text only. It does not create a proposal, mailbox draft, or send; saving for review and approving remain separate actions.
- Selected text has a 15-minute lease. An identical cached result retains its original generation time and does not extend the lease. Source, message-text digest, note revision, policy/configuration, and composer revision are fenced before and after asynchronous work so stale results are not applied. The provider request is a single Responses POST with `store:false`, no tools, and strict JSON schema; incomplete/refusal/malformed output is rejected, usage settles before the final freshness check, and there is no automatic retry.
